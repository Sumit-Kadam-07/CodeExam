1. Project Overview

The Smart Coding Exam System is a full-stack web application for conducting online coding examinations. It allows administrators to create exams with coding questions, and students to attempt them with real-time code execution using the Monaco Editor.

Key Features

  • Role-based access: Admin and Student roles with JWT authentication
  • Exam Management: Create, edit, publish/unpublish exams
  • Question Management: Manual, AI-generated, and file-upload question creation
  • Monaco Code Editor: Industry-standard code editor with syntax highlighting for Java, Python, C, C++
  • AI Question Generation: Generate questions via Groq (Llama 3.3) or Ollama
  • Code Execution: Local compiler/interpreter or Judge0 API
  • Auto-grading: Automated test case evaluation
  • Student Dashboard: Results, leaderboards, profile management
  • Admin Dashboard: Analytics, grade submissions, manage students

App.tsx

frontend/frontend/src/App.tsx

Core routing component. Uses wouter (lightweight React router) with Switch and Route. All pages are lazy-loaded with React.lazy() and wrapped in Suspense with a spinner fallback. The AuthProvider context wraps the entire app. Routes are organized by:

  • Public: Home (/), Login (/login), Register (/register)
  • Admin: /admin/dashboard, /admin/manage-exams, /admin/exam/add, /admin/exam/edit/:id, /admin/exam/:id/question/add, etc.
  • Student: /student/dashboard, /exam/:id, /student/my-results, /student/profile, etc.

Protected routes enforce role-based access (ProtectedRoute component).

3.2 Routing & Auth

ProtectedRoute.tsx

frontend/frontend/src/components/auth/ProtectedRoute.tsx

Route guard component. Checks if user is authenticated via AuthContext. If not initialized, renders nothing. If not logged in, redirects to login. If user role doesn't match allowed roles, redirects to home. Otherwise renders children.

AuthContext.tsx

frontend/frontend/src/context/AuthContext.tsx

Global authentication state using React Context. Provides:

  • user — Current user object (username, fullName, role, profilePicUrl)
  • login(user) — Sets user state
  • logout() — Clears tokens and user data from localStorage
  • updateUser(updates) — Partial updates to user state
  • initialized — Boolean flag indicating auth state is loaded

On mount, checks for existing JWT token. If found, calls /auth/me to validate. If not, attempts to restore user from localStorage.

  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) NOT NULL,           -- ROLE_ADMIN / ROLE_STUDENT

  mobile VARCHAR(20),

  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP

    CREATE TABLE exams (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  created_by_user_id BIGINT NOT NULL,
  title VARCHAR(200) NOT NULL,

  duration_minutes INT NOT NULL,
  is_published BOOLEAN DEFAULT TRUE,

  ends_at DATETIME,

    6. Key Workflows

    6.1 Authentication Flow

    1. User enters credentials on LoginPage → POST /api/auth/login
    2. Backend validates credentials, returns JWT token + user data
    3. Frontend stores token in localStorage, user data in AuthContext
    4. Subsequent API calls include Authorization: Bearer header
    5. JwtAuthenticationFilter validates token on every request
    6. ProtectedRoute checks auth state before rendering protected pages

    6.2 AI Question Generation Flow

    1. Admin enters topic, language, difficulty, marks → AiGenerateTab
    2. POST /api/ai/generate → AiQuestionController
    3. AiQuestionService.buildQuestionPrompt() creates structured JSON prompt
    4. AiClient.callApi() sends prompt to Groq/Ollama
    5. AI returns JSON response parsed into AiGenerateResponse
    6. Frontend populates QuestionForm with AI-generated data
    7. Admin reviews and clicks "Save Question" → POST /api/admin/exam/:id/question
    8. AdminService.addQuestionWithArrays() validates and saves question + test cases to DB

    6.3 File Upload Multiple Questions Flow

    1. Admin uploads a file (PDF/DOCX/TXT) containing 5 questions
    2. POST /api/ai/upload?examId=X → FileUploadController
    3. FileExtractionService.extractText() extracts text from file
    4. AiQuestionService.generateMultipleQuestions() builds multi-question prompt and calls AI
    5. AI returns JSON array of AiGenerateResponse objects
    6. Controller iterates over each question, validates, and saves via AdminService.addQuestionWithArrays()
    7. Returns response with savedCount, questionIds, failedCount, errors
    8. UploadQuestionTab shows success/error counts to admin

    6.4 Exam Taking Flow

    1. Student views available exams on StudentDashboard
    2. Clicks exam → GET /api/student/exam/:id → loads questions
    3. ExamPage shows Monaco Editor for each question with timer
    4. Student writes code, can run/test via POST /api/code/run
    5. On submit → POST /api/exam/:id/submit → saves code + evaluates test cases
    6. ExamService calculates score, creates ExamResult
    7. Student redirected to ResultConfirmation

    6.5 Grading Flow

    1. Admin views exam results → GET /api/admin/results/:id
    2. Clicks "Grade" → GradeSubmission page shows code + test case results
    3. Admin reviews code, enters marks per question, adds remarks
    4. POST /api/admin/results/:id/grade saves marks, updates status

    7. Setup & Running

    • Node.js 18+
    • Java 17+ (Maven wrapper included)
    • MySQL 8+
    • For local code execution: JDK, Python, GCC/G++ installed
    • For AI: Groq API key (free) or Ollama running locally

npm install
npm run dev
