Smart Coding Exam System

Database documentation

1. Overview

The application uses a MySQL database named smart_coding_exam. It stores users, exams, coding questions, test cases, results, code submissions, and activity/audit events.

The backend connection is configured in backend/src/main/resources/application.properties. The default database host is localhost:3306. Connection values can be supplied through MYSQL_URL, MYSQL_USER, and MYSQL_PASSWORD environment variables.

2. How the database is created

  1. Create the MySQL database.
  2. Start the Spring Boot backend.
  3. Hibernate compares the Java entities with the schema and creates missing tables or compatible columns.
CREATE DATABASE IF NOT EXISTS smart_coding_exam
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

The backend setting spring.jpa.hibernate.ddl-auto=update keeps the schema aligned with the entity classes without deleting existing data.

Important: database/schema_mysql.sql is a useful initial schema reference, but it is older than the current entity model. The active schema is maintained by Hibernate when the backend runs.

3. Database relationships

users ──< exams ──< questions ──< test_cases │ │ │ └──< exam_results ──< coding_submissions │ │ └────────────────────┘ │ activity_logs

Each “one-to-many” relationship uses a foreign key. For example, a question belongs to one exam through questions.exam_id, while an exam may have many questions.

5. Data flow

  1. An admin creates an exam; a row is stored in exams.
  2. The admin adds questions and test cases; they are stored in questions and test_cases.
  3. A student starts an exam; the system creates or updates an exam_results record.
  4. For each coding answer, the system stores a row in coding_submissions.
  5. Code evaluation updates the submission with output, errors, passed tests, timing, and score.
  6. Final marks and percentage are saved in exam_results.
  7. Important student actions are recorded in activity_logs.

6. Integrity and security

  • Primary keys use auto-increment numeric IDs.
  • Foreign keys enforce links between parent and child records.
  • Several child records cascade when their parent exam/question/result is deleted.
  • Unique constraints prevent duplicate usernames and duplicate result attempts for the same student, exam, and attempt number.
  • Passwords are stored as BCrypt hashes, never plain text.
  • Indexes support common lookups such as published exams, exam questions, student submissions, and student results.

7. Older reference-only tables

The SQL reference script also defines attendance and evaluation_results. The present Java entity model does not use these tables. Current code evaluation details are stored directly in coding_submissions.
